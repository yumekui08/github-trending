# 0039 要約にインストールの手順を持たせる、リポジトリごとの OGP 画像を作る

- 日付：2026-10-11
- 状態：決定

## 背景
0038 の続き（SEO の第2弾）。ツールの名前での検索は「〇〇 とは」「〇〇 使い方」のほか「〇〇 インストール」が多い（Google の検索候補）。今の要約はインストールのコマンドを `how_to_use` の文の中に書いていて、見出しにも出ず、コピーもしにくい。また、詳しいページを X や Discord に貼ったときのカードの画像が、どのページもサイトの題字の画像で、何の記事か分からない。

## 決定
- **`install`（インストールの手順）を要約に足す**：文字列の配列（6個まで）。README などの材料に書かれているコマンドだけを写し、1つのコマンドは全体を `` ` `` で囲む。前提や補足は囲まずに文で。材料に書かれていなければ `[]`（推測でコマンドを作らない）。`how_to_use` は「インストールしたあとの最初の一歩」にし、インストールのコマンドを繰り返さない
  - 形の検査（schema）では必須にしない（今までの要約にはないため）。routine には必ず書くよう `docs/routine.md` に書く。今までの要約は、90日たって書き直すときに入る
  - サイトでは「〇〇 のインストール」の節（「できること」の次）に出す。コマンドは灰色の塊にし、「コピー」のボタンを付ける（JavaScript がなくても読める）
- **リポジトリごとの OGP 画像**：`r/owner/name/og.png`（1200×630）。紙の色の地に、題字・表罫・「リポジトリ解説」、アカウント名と言語、リポジトリ名（Gelasio）、`what`（BIZ UDPゴシック、2行まで）、下に標語とドメイン。サイトを作るときに Pillow で描く
  - フォントは、サイトで使っている BIZ UDPゴシック（Bold）と Gelasio を `src/github_trending/fonts/` に同梱する（どちらも OFL。ライセンス文も置く）。Actions で毎回フォントを入れなくてよく、どこで作っても同じ画像になる
  - 依存に Pillow を足す
  - URL に `?v=要約した日` を付け、書き直したら SNS の古いキャッシュを使わせない。構造化データの `image` もこの画像にする
  - 107 件で、サイトを作る時間は約 9.5 秒（1件 0.05 秒ほど）。件数が増えて遅くなったら、変わっていないものを作り直さない工夫を考える
