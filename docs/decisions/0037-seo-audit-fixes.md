# 0037 SEO の点検を受けた直し：日付の一覧を検索に載せない、分野ごとの一覧、トップの題、構造化データ、ヘッダー、AI ボット

- 日付：2026-10-07
- 状態：決定（0026 のトップの題、0035 の詳しいページの構造化データを改める）

## 背景
本人が SEO 点検のプラグイン（claude-seo）でサイトを点検した。総合点は推定 76/100。検索に載らなくなるような急ぎの問題はなかった。直すことの多くは小さく、いくつかは本人に決めてもらった。

## 決定
- **日付を指定した一覧（`/d/日付/`、`/d/日付/weekly/`、`/d/日付/monthly/`）は検索に載せない**：`noindex, follow` を付け、sitemap から外す。前の日との重なりが 42〜76%、トップと最新の `/d/日付/` は 99% 同じだったため。リンクはたどってもらうので、詳しいページへの道は残る。トップ・`/weekly/`・`/monthly/` は載せる
- **分野ごとの一覧 `/t/英字の名前/`**：その分野のタグが付いた解説を、要約した日の新しい順にすべて並べる。分野の一覧 `/t/`（件数の多い順）も作る。英字の名前は `build_site.py` の `TAG_SLUGS`（schema の分野の一覧と同じ25個）。詳しいページのタグ、「本日の分野」、「同じ分野の記事」の「すべて見る」、フッターの「分野別」から入れる。sitemap に載せる。日付の一覧を載せなくなっても、古い詳しいページへの道がなくならないように
- **確かさが「低」の解説は検索に載せない**：`noindex, follow` を付け、sitemap から外す。サイトでは今までどおり読める（本人が選んだ）
- **トップの題**：「github新聞｜GitHub Trending を毎朝日本語で」（週次・月次は「…の週次ランキングを日本語で」など）。0026 の「github新聞 だけ」を改める。タブでは先頭の「github新聞」が見え、検索では何のサイトかが分かる（本人が選んだ）
- **構造化データ**：日付に時刻と時差（要約した日の 7:00、日本時間。フィードと同じ）。著者に `/about/` の URL、発行元にロゴ、`SoftwareSourceCode` に一文の説明。パンくずは「トップ → 主な分野 → 記事」の3段。`article:published_time` も時刻付き
- **`_headers`**（Cloudflare Pages の応答ヘッダー）：HSTS・X-Frame-Options・nosniff・Referrer-Policy・Permissions-Policy。`?v=` 付きで参照する CSS・ロゴ・favicon は1年キャッシュ（immutable）。CSP は、インラインのスクリプトと style 属性があるので入れない
- **AI ボット**：Cloudflare が学習用の AI ボットを 403 で止めているのに合わせ、robots.txt でも GPTBot・ClaudeBot・CCBot などを `Disallow: /` にする。検索用のボット（Googlebot、OAI-SearchBot など）は今までどおり許す（本人が選んだ）
- **トップ記事のグラフ**：`loading="lazy"` にして、隠れている方（ライト／ダーク、スマホでは両方）を読み込まないようにする
- **詳しいページ**：「材料」を読める名前で出す（meta → リポジトリ情報、tree → ファイル構成、manifest:pyproject.toml → pyproject.toml（依存の定義）など）。スター数に「いつ時点か」（最後に Trending で見た日）を添える
- **`/about/`**：運営者（GitHub の yumekui08）と、誤りの連絡先（GitHub の Issue）、「公開する前に人が一つずつ確かめてはいない」ことを事実どおりに書く
- **要約の書き出し**（`docs/routine.md`）：`short` の最初の文は、リポジトリ名を主語にする。段落だけ抜き出されても何の話か分かるように（本人が選んだ。これから書く要約にだけ効く）
- ロゴのリンクの `href=""` を `./` にする
